# 清凉校园 · 热浪行动

**一个校园微气候改善决策游戏（等轴 2.5D 推演）。**
你是校园里的学生规划志愿者，在有限预算和施工档期下，为校园的每块地选择降温改造，
然后接受一组不寻常的验收条件：**不仅整体要变凉，脆弱群体的改善幅度还不能低于平均。**

> ⚠️ 这是**教育性模拟游戏**，不是热环境预测工具，也不是任何学校的官方规划。
> 校园地名做了风格化重构，地表热指数、人数、人群构成、造价与降温效果**全部是原型模拟参数**，
> 不是实测温度，也不是真实人口数据。请勿用于任何真实区域的评估。

## 0. 免安装试玩（推荐）

解压后直接双击根目录的 `index.html`（会自动进入 `portable/index.html`），或双击 `启动游戏.cmd`。
这是纯本地静态版本，不需要 Node.js、不需要服务器，也不需要输入任何网址。

> 根目录 `index.html` 只在 `file://` 下自动跳转到免安装版；通过 `npm run dev` 或线上 http 访问时仍是正常源码入口。

## 1. 本地运行与构建

```bash
npm install        # 安装依赖
npm run dev        # 开发服务器 http://localhost:5174
npm run build      # 生产构建（tsc 类型检查 + vite build）
npm run preview    # 预览构建产物 http://localhost:4174
npm test           # 全部测试（vitest，108 项）
npm run typecheck  # 仅类型检查
npm run gen:shots  # 浏览器验收截图（需 Playwright 浏览器）
npm run build && node serve-dist.mjs  # 先构建，再零依赖预览 http://localhost:5174
```

> `http://localhost:5174` / `:4174` 只是本机启动服务后的本地地址，不是公网网址；只想试玩可直接使用免安装版。

Node.js 22 开发，构建产物是纯静态文件，兼容 Node.js 20+。

**演示形态**：桌面端使用宽屏小程序视口（约 2.06:1）居中呈现（顶部为状态栏 + 微信风格胶囊按钮，弹窗与引导都锁在视口内）；窄屏（≤1080px）自动退回全屏版式。

## 2. 它是什么

一个 **14×14 的等轴 2.5D 微缩校园**：教学楼、图书馆、中心广场、学生公寓、学者餐厅、
田径运动场、校医院、附属幼儿园、后勤保洁休息点、外卖集散点，以及校园边缘的唐岛湾水岸。
玩家拥有**预算**（以及一个可连续旋转到任意角度的视角），为地块选择八种改造手段：

| 工具 | 造价 | 半径 | 遮阴 | 蒸散 | 舒适 | 适合解决的问题 |
| --- | --- | --- | --- | --- | --- | --- |
| 行道树 | 3 万 | 2.0 | 15 | 6 | 5 | 道路、广场边缘的持续暴晒 |
| 遮阳棚 | 6 万 | 1.4 | 22 | 3 | 16 | 排队、等单、休息等“必须停留”的暴晒点 |
| 浅色反光铺装 | 5 万 | 2.2 | 0 | 8 | 3 | 大面积硬质地面的整体蓄热 |
| 透水铺装 | 8 万 | 2.2 | 0 | 9 | 4 | 蓄热 + 暴雨积水的双重问题 |
| 雾森降温 | 7 万 | 1.6 | 2 | 24 | 12 | 午后人流密集的高温公共空间（耗水） |
| 浅水景观 | 12 万 | 2.6 | 4 | 20 | 18 | 广场核心区的高强度暴晒 |
| 饮水补给点 | 4 万 | 1.2 | 2 | 0 | 24 | 户外劳动者的补水与中暑风险 |
| 绿色屋顶 | 10 万 | 2.0 | 5 | 14 | 2 | 建筑屋顶向四周与顶层房间放热 |

（数值均为**模拟参数**，用于比较取舍，不是工程预算或经认证的实测效果。）

## 3. 玩法与交互

### 3.1 随时放置，只受预算限制

没有回合行动点、没有冷却、没有“本回合还能放几个”的心算。
选一个工具、在地图上点一下，就这么简单：**看数字 → 放改造 → 推进时间看变化**。

### 3.2 时间会改变人群
同一个校园，午后的问题在中心广场（学生穿行、骑手等单），傍晚的问题在田径运动场
（塑胶跑道白天吸的热在傍晚放出来）。地块的人数和**户外暴露比例**都随时刻变化：
教学楼 14:00 只有 15% 的人算暴露，食堂取餐高峰 12:00 有 75% 在排队，
而后勤、门岗、绿化与骑手几乎 100% 在户外。

### 3.3 每关一眼可辨的地图
同一个校园，但每个关卡在视觉上有明显区隔：

- **天光与太阳**随时刻变化（晨光偏冷、正午亮白、午后偏暖、斜阳橙金），太阳位置也随之移动；
- **天气氛围**叠在地图上：黄色预警偏暖、橙色预警橙红光晕、雷阵雨蓝灰并飘落雨丝；
- **极热地块**（热指数 ≥ 85）加一圈亮边并标出数值；
- **任务聚焦点**：开局用黄色虚线圈标出本关的重点区域（第 1 关中心广场、第 3 关田径运动场、
  第 4 关后勤休息点 / 校医院 / 幼儿园 / 外卖集散点），放下第一处改造后自动消失。

### 3.4 实时效果预览
选好工具后把鼠标移过地图，会出现**效果预览卡**：加权热指数、户外高暴露人数、
脆弱群体高暴露人数、公平差、舒适度各自变化多少，一眼可见。
地图上还会高亮这颗工具的影响范围（距离衰减后的实际覆盖）。

### 3.5 可解释的参谋建议
“参谋建议”是**本地规则推理**（不调用任何大模型）：枚举当前合法的“工具 × 地块”组合，
按改善效果 ÷ 造价排序，给出前三条并说明理由（哪块地、谁是主要人群、这类工具擅长解决什么）。
地图上会用「荐」标记候选点位。如果完全不想思考，直接点 **✦ 自动布置方案**——
它会按本关的任务目标一次铺好一套**直接达标**的方案，不用再手动调整。

### 3.6 事件与选择
推进时间会触发预警升级、用水紧张、纳凉点是否开放等事件，其中一些是**两难选择**
（例如“这一份预算给后勤休息点，还是再给广场加一处喷雾？”）。选择会影响公众支持度与后续态势。

### 3.7 复盘与行动清单
推演结束会给出**星级、逐条目标结果**与一句话诊断。
`/plan` 页面把当前方案整理成可打印的**清凉改造行动清单**，并说明这份清单的社会意义。

**重做本关会清空地图上的改造**：点「重做本关」会关闭复盘并把本关回到开局——玩家放置的改造全部清空、
预算与时刻复位（关卡自带设施保留），**但决策记录保留**，并追加一条「重做本关」说明；不会再弹一次关卡
简报，调整完可再次「结束推演 · 生成复盘」。
每关的推演进度各自保留：切到别的关卡再回来，看到的仍是你上次离开时的样子。

### 3.8 多视角观察

地图像摆在桌上的微缩模型一样**绕竖直轴转动**：拖右下角的滑块，拖到多少度就转多少度
（也可按 `Q` / `E` 每次微调 15°，或点 ⌂ 回到正北朝向）。
地面在任意角度都是正确的斜投影，建筑的可见立面按外法线连续切换、光照固定在世界方向；
遮挡关系会同步重新计算，被高楼挡住的地块换个角度就能点到——
这就是“有些地块要到另一个角度才能操作”的原因。

**放下去之后会告诉你效果如何。** 每次放置改造，地图左上角会弹出一张反馈卡：
高暴露人数、脆弱群体、公平差、舒适度的变化都会用人话说明；
如果数值没动，它会解释为什么（例如“热指数降了但仍在高暴露线以上，再加一处相邻的改造就能连起来”），
而不是让玩家对着一动不动的数字猜。

### 3.9 上手引导

首次打开会自动进入一段**指令式引导**：从选工具、看预览、放置、读反馈、认识图层开关、认识右侧任务目标、转视角、
用参谋建议、用「在地图上标出并采用 / 自动布置方案」、给图书馆设置纳凉时段到推进时间，每一步都在界面上用高亮圈指出该点哪里，完成后自动进入下一步（可随时跳过）。
第一步会先把其余界面压暗、聚光灯打在左侧面板上，并提醒玩家"引导主要在左侧进行"。
想重看时，打开右上角「控制台 → 新手引导」即可重新播放。

## 4. 五个关卡

| 关卡 | 场景 | 天气 | 预算 | 想说的事 |
| --- | --- | --- | --- | --- |
| 1 | 正午的中心广场 | 常规晴热 | 20 万 | 有限预算下的第一优先级：人多 × 最晒 × 必须停留 |
| 2 | 热浪橙色预警 | 橙色预警 | 30 万 | 降温不只是加树：改变大面积硬质下垫面的反射与蒸散 |
| 3 | 傍晚的运动场 | 黄色预警 | 28 万 | 热暴露是“人 × 地点 × 时间”的乘积 |
| 4 | 一个都不能少 | 橙色预警 | 62 万 | 公平不是平均：脆弱群体的改善不能低于平均 |
| 5 | 清凉校园 · 沙盒 | 常规晴热 | 不设限 | 预算不设限，自己出一道题 |

各关的具体验收目标与事件见 [`docs/rules.md`](docs/rules.md)。

### 公平差：这个作品最想讲的一个指标

```
公平差 = 脆弱群体高暴露率 − 学生高暴露率   （单位：百分点 pp）
```

如果只看平均温度，一个“把中心广场浇得很凉、却把后勤休息点晾在一边”的方案也会显得很漂亮。
用**高暴露率之差**衡量，就能暴露这种“平均值陷阱”。

第四关的核心目标就是把这个差值压到 10 pp 以内，而**开局是 11.5 pp——本来就不达标**。
难点在于：参谋建议按“改善效果 ÷ 造价”排序，天然偏向人数最多的中心广场；
而能真正缩小差距的，恰恰是后勤休息点、外卖集散点、校医院、幼儿园这些
**人数少但最脆弱**的点位。只跟着建议走，公平差几乎一动不动（仍停在 11.9 pp 左右），
必须自己把预算投过去才压得下来——这正是本关的核心目标，也是答辩时最有说服力的一段。

`src/lib/balance.test.ts` 用机器人玩家守住了这两条：认真规划能拿 3 星，
只跟建议走拿不到满分。

## 5. 规则引擎（全部是纯函数）

所有核心计算都在 `src/lib/engine.ts` 中实现为纯函数，与 React 解耦，可单独测试与逐条讲解答辩：

```
地表热指数 = clamp( 基础热度 × 时刻系数 × 天气系数 + 事件修正
                    − 遮阴降温 − 蒸散降温 , 12 , 100 )

户外暴露人数 = Σ 地块人数 × 该地块该时刻的户外暴露比例

加权平均热指数 = Σ (heat × 户外人数) / Σ 户外人数

公平差 = 脆弱群体高暴露率 − 学生高暴露率
```

- **距离衰减**：`1 − (d/R)^1.6`，每种影响（遮阴 / 蒸散 / 舒适度）都有单点上限，避免堆设施刷出不真实的低温。
- **脆弱度权重**：老人 1.9、儿童 1.8、户外劳动者 1.5、骑手 1.4，学生基准 1.0。
- **高暴露阈值**：地表热指数 ≥ 72 且人在户外。

完整的公式、关卡设计与参数表见 [`docs/rules.md`](docs/rules.md)。

## 7. 无障碍与响应式

- 地图与全部控件均可用焦点导航（外接辅助设备可用）；
- 状态不只靠颜色：同时使用文字（高暴露 / 舒适）、数值标签、符号（老 / 童 / 劳 / 骑）与形状；
- SVG 地图提供 `role="img"` 与动态 `aria-label`；
- 弹层使用 `role="dialog"` + `aria-modal`，按钮均有 `:focus-visible` 描边；
- 尊重 `prefers-reduced-motion`，可关闭全部动效；
- 已验证视口：1440×900（笔记本）、1080px 断点（平板纵向与横向）、390×844（手机）；手机端无横向溢出。
- **手机端完整的「横版小程序」**：≤1080px 时不再使用标签页布局，而是把完整界面
  （左栏 + 地图 + 右栏 + 工具坞，16:10 设计稿）**整块等比缩放**到一屏内——三栏与地图同屏可见、
  面板自动缩小；竖屏打开会自动旋转 90° 成横屏（转手机即正看），首次触控自动进入全屏隐藏地址栏。

## 9. Ubuntu / Nginx 部署

服务器在**部署阶段**安装依赖并构建，现场不执行 `npm install`。

```bash
# 一次性：安装 Node.js 22 与 nginx
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt-get install -y nodejs nginx rsync

# 部署
npm ci
npm run build
sudo mkdir -p /var/www/cool-campus
sudo rsync -a --delete dist/ /var/www/cool-campus/

sudo cp nginx.conf /etc/nginx/sites-available/cool-campus
sudo ln -sf /etc/nginx/sites-available/cool-campus /etc/nginx/sites-enabled/cool-campus
sudo nginx -t && sudo systemctl reload nginx
```

或直接使用脚本（自动完成依赖安装、测试、构建与发布）：

```bash
./deploy.sh "$PWD" /var/www/cool-campus
```

**访问路径**：`/`（推演）、`/method`（方法与边界）、`/plan`（行动清单）。
`nginx.conf` 已配置深层路由回退，刷新任意路由均正常。本项目**无后端进程、无数据库、无环境变量**。

## 11. AI 工具使用说明

- **背景音乐**为 AI 生成音频（原始文件含 Google C2PA trainedAlgorithmicMedia 标记），团队完成选曲、剪辑与压缩；游戏运行时不调用 AI 服务。
- 作品中的**参谋建议是本地规则推理**，枚举“工具 × 地块”并按可解释的评分排序，**不调用任何大模型 API**；
- 现场演示不依赖网络：地图、图标、配乐全部本地生成；
- 本文档与代码中的模拟参数、关卡数值均经人工设定与测试校准（见 `lib/balance.test.ts` 的“3 星可达”回归测试）。
